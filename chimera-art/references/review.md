# 审核页和审核结果

## 生成审核页

审核页是工作区根目录的 `review.html`（第一次从本技能的 `assets/review.html` 复制过来，不要改它）。每一批只需要重写 `state/review_data.js`，然后请用户双击打开 `review.html`（已经开着的按 F5 刷新）。不要用命令打开浏览器。

`state/review_data.js` 的内容（UTF-8；图片路径都相对于工作区根目录，用正斜杠）：

```js
window.REVIEW = {
  id: "第3批",                 // 每批唯一，审核结果里会带上它
  title: "第 3 批（8 张）",
  mode: "items",               // 选画风那一步用 "style"
  items: [
    { n: 14, file: "part_sash.png", cn: "仪式肩带（人族部件）",
      img: "candidates/part_sash__v1.png",          // 你的首选
      alts: ["candidates/part_sash__v2.png"],       // 其他候选，可以没有
      check: "✅ 单条肩带、朝右、纯白底" }
  ]
};
```

选画风（`mode: "style"`）时，每个 item 写 `label`（A / B / C）、`cn`（方向的中文名，如"清透日系"）、`img`，不写 `n` 和 `file`。

注意：`id` 每批都要换（页面用它记住用户的选择）；字符串里不要出现没转义的双引号和换行。

## 审核结果的格式

用户点"生成审核结果"后会粘贴回来这样一段：

```
$chimera-art 审核结果 第3批
通过：14,15,16,18
换候选：16=候选2
重画：17（脸太幼，要更成熟）；19
没审：20
```

- 数字是清单编号 `n`。
- **通过**：把首选（或"换候选"里指定的那张，候选2 = `alts[0]`，候选3 = `alts[1]`）复制进 `art_pack/<file>`，状态记为 approved。
- **重画**：括号里是用户的意见，译成英文按 prompting.md 第 5 节加上，放进下一批；没写意见就按你自检时看到的问题改，或换个随机种子再出。
- **没审**：留到下一批的审核页里再给他看（不用重新出图）。
- 选画风的结果是 `风格选择：B（意见）`，可能还有一行 `其他意见：方案C：……`。把其他方案的意见也考虑进风格方向里（例如"C 的配色好看"→ 在 `style.note_en` 里加上 C 的配色）。

用户也可能不用审核页，直接用自己的话说（"都可以，就 17 的脸太幼"）。照意思处理，不要求他改格式。

## 补图请求的格式（Claude 写的）

```
$chimera-art 【补图请求】来自 Claude（《奇美拉纪元》）
请按美术技能（或 ChatGPT 项目指令）和清单生产下面这些资产，按文件名找对应的项：每项照常自检，再请我审核。文件名必须和下面完全一致。
（可能有一行：风格已更换：……）

1. 【13】part_sac.png　毒液吊坠（虫族部件）　—— 重做：背景有阴影，抠图后边缘发灰
2. 【47】body_floater_enemy.png　幽体反派·幽冥女帝（女）　—— 缺失

（共 2 项。……）
```

按 flow.md「补图」做（第二行里的"ChatGPT 项目指令"是给备用方案用的）。按**文件名**找清单里的项（编号可能和你的清单对不上，以文件名为准）。
某一行的原因后面可能附了完整的英文提示词（"需要大改"时 Claude 会附上），这时用它代替清单里的提示词。
