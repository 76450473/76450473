# 美术工作室：GPT 生图 + 两级审核

工作区里有 `GPTapi.txt`（用户的 OpenAI Key）时，美术由你调用 OpenAI 图像接口生成。你先初审，用户再复审，通过的图才进游戏。没有 Key 时走手动模式（用户自己出图，见 `art-pipeline.md`）。两种模式可以混用。

## 0. 铁律：Key 与花钱

**Key**
- **绝不打开 `GPTapi.txt`**：不用 Read，也不 cat、grep、type。不要把 Key 写进任何文件、命令行参数、日志、提交或聊天。只有 `art_studio.gd` 会读取它，并且只发给接口地址。`setup_workspace.sh` 会在 `.claude/settings.json` 里加一条禁止读取它的规则。
- 用户把 Key 直接贴进聊天时：不要复述它。请用户把 Key 存进 `GPTapi.txt`，并建议去 OpenAI 后台作废这个 Key、换一个新的，因为它已经出现在聊天记录里。
- 游戏仓库在 `游戏/` 里，`GPTapi.txt` 和 `美术资产/` 都在仓库外面。模板的 `.gitignore` 也排除了它们，以防用户放错位置。

**花钱**
- 每次 `gen` 之前先跑 `plan`，把"N 项 × n 张 ≈ $X"告诉用户，用户同意后才生成。
- 用户给过预算的（例如"10 美元以内不用问我"），在预算内直接做，用 `--max-usd` 限住。
- `gen` 预计超出单次上限会直接拒绝。上限默认 $3，可以在 GPTapi.txt 用 `budget=` 修改，或用 `--max-usd` 临时放宽，但放宽前必须先征得用户同意。
- 自动重画每项最多 `max_rounds` 轮（默认 3）。到上限后不再重画，挑最好的一张交给用户，并在 note 里写清问题。
- 汇报时附上累计花费（`status` 里有）。这是按官方价的估算，以 OpenAI 账单为准。

## 2. 一轮完整流程（命令）

`W` 是工作区路径（一般是 `.`），`S=SKILL_DIR/scripts`。

```bash
bash $S/art_studio.sh . status               # 每次开始先看：等谁、下一步、花了多少
bash $S/art_studio.sh . plan anchor          # 列清单 + 费用 → 告诉用户，等同意
bash $S/art_studio.sh . gen anchor           # 生成候选（超过 5 项用 run_in_background）
#   → 你初审：逐个 Read 美术资产/候选/_对比/<id>.png → 写 美术资产/初审.json（§4）
bash $S/art_studio.sh . apply                # 挑中的进 待复审/，不行的标记重画
bash $S/art_studio.sh . plan redo && bash $S/art_studio.sh . gen redo   # 有重画时（同样先报费用）
#   → 再初审 → apply，直到每项都挑出图或到达轮数上限
bash $S/art_studio.sh . trial                # 试装截图 + 审核页面 → 你先 Read 截图自查（§5）
bash $S/art_studio.sh . serve                # run_in_background！自动打开用户的浏览器
#   → 用户提交后 serve 自己退出（你会收到后台任务结束的通知），或者用户说"复审好了"
bash $S/art_studio.sh . user-apply           # 通过 → 已通过/；不要 → 记下用户意见
bash $S/art_studio.sh . sync                 # 通过的图进游戏：抠图、上色、检查、4 张截图
#   → 被退回的：按 §7 改提示词 → 初审.json 写 {"<id>": {"prompt": "..."}} → apply → plan redo → gen redo → 循环
```

**批次顺序**：
1. `anchor`：定调批，6 张（人形和六足骨架、复眼、毒腺囊、毒图标、腐沼背景）。先把画风定下来。
2. 然后依次是 `p1`（40 项）→ `p2` → `p3`。

定调批通过后，后续的骨架、部件、图标会自动带上已通过的同类图作为**风格参考**（`style_ref=auto`），整套画风才统一。

一批太大时可以拆开做，比如 `gen part_banner,part_bloom,...` 或者先做 P1 里的部件。选择写法有 `anchor`、`p1`、`p2`、`p3`、`all`、`redo`，也可以写资产 id，用逗号分隔。点名的 id 即使已经有图也会重画。

**等待复审期间**继续开发游戏，不要干等。但不要 sync 用户还没通过的图。

**gen 中途被打断**（会话超时、断网）不要紧：每生成完一项就会存盘。重跑同一条 `gen`，会跳过已经有候选的项，接着做剩下的。

## 3. 生成细节

- **提示词来源**：`data/art_manifest.json` 推导出的清单，和《美术资产清单与提示词.txt》同源。GPT 版本会自动做这些改写：
  - 去背景类（部件、骨架、Boss、图标）改成要真正的透明背景，边缘比白底抠图干净；
  - 需要裁切的资产加上构图提示；
  - 反向提示词并入句末的 "Avoid:"；
  - 有风格参考时，在开头加上"只学画风，不抄内容"的说明。
- **覆盖提示词**：你在 初审.json 里写的 `prompt` 会替换清单提示词（存在 记录.json 里），以后每轮都用它。写完整的英文提示词，不要写 "Avoid:"，工具会自动加。
- **候选数与尺寸**：每项 n 张（默认 3）。尺寸按比例取 1024×1024、1536×1024 或 1024×1536，导入时再裁到游戏需要的尺寸。
- **对比拼图** `候选/_对比/<id>.png`：
  - 上排是原图，从左到右依次是第 1..n 张（格子左上角的黄点数就是序号）；
  - 下排是游戏导入器处理后的样子（去背景、转灰度、裁切），棋盘格表示透明。
- **导入器警告**会直接打在 gen 的输出里（例如"彩色面积偏大""主体太小""几乎没去掉背景"）。这些都是硬伤，挑图时要考虑进去。
- **风格参考**：
  - 骨架和部件，参考已通过的骨架和部件（定调批优先），外加 `美术资产/风格参考/` 里的图，最多 3 张；
  - 图标只参考已通过的图标；
  - 背景、卡图、界面、Boss 不带参考，以免照抄构图；
  - 用 `--no-ref` 可以单次关闭，GPTapi.txt 里写 `style_ref=off` 则全部关闭。

## 4. Claude 初审：打分标准与 初审.json

**原则**：你是第一道关，不是传话筒。明显有问题的图不要交给用户，宁可重画。用户只想看到"能用、而且好看"的图。

逐项 Read 对比拼图，必要时 Read 单张原图（`美术资产/候选/<文件名>`）看细节。按下面 7 条检查：

1. **主体对不对**：对照 cn 名称和提示词里的 Subject。只能有一个物件，没有多余的肢体、碎片、文字、水印、边框。
2. **去背景干净**（看下排）：没有白边，没有残留的底色块，主体没有被啃掉。图标必须是单一的白色剪影。
3. **朝向和连接端**：部件和骨架侧视朝右，Boss 朝左；连接端的位置以提示词为准（肢体根部在左，冠类从底部往上长，尖牙从顶部往下垂）。
4. **灰度**：palette 模式只有提示词里说的发光部位是鲜绿色，其余必须是灰度。导入器报"彩色面积偏大"就是不合格。
5. **风格统一**：和 `已通过/` 里的同类图比较线宽、明暗层次、细节密度。定调批之后这一条最重要，比较时 Read 一两张已通过的图。
6. **小尺寸可读**：下排小图里轮廓仍然清楚；棋盘上的棋子大约只有原图的 1/4 大。
7. **场景类**（背景、卡图、卡背、界面）：
   - 不能有文字；背景图里不能有角色；
   - 背景中部要留出战斗空间；
   - 卡图不能带卡框。

**取舍**：
- 最好的一张写成 `pick`。
- 第二张也合格、而且有明显不同的特点，写成 `alt`，给用户一个选择。不要凑数。
- 全都不合格就 `redo`：写清楚具体原因，并给出改好的 `prompt`。
- 已经到第 `max_rounds` 轮时只能 pick。在 note 里如实写明缺点，比如"三轮都偏写实，这张最接近；不满意可以退回，我再换个写法"。

**初审.json**（写到 `美术资产/初审.json`，UTF-8）：
```json
{
  "part_sac": {"pick": 2, "alt": 3, "note": "第 2 张轮廓最清楚、灰度干净；第 3 张备选，囊更饱满"},
  "body_biped": {"redo": "头太小，手臂和身体粘在一起", "prompt": "<完整的新英文提示词>"},
  "icon_energy": {"prompt": "<完整的新英文提示词>"}
}
```
- `pick` / `alt`：序号（1..n，按对比图从左到右）或文件名。
- `note`：给用户看的中文理由，一句话，要具体。用户在审核页面上会看到。
- `redo`：重画原因（中文）。可以同时给 `prompt`；不给就沿用上一轮的提示词，但同一个提示词重画通常还会出同样的问题，所以最好给。
- 只写 `prompt`：只改提示词，用于用户退回之后。
- 已经交给用户的项（试装后发现问题）：`{"redo": "原因"}` 会撤回并重画；`{"note": "..."}` 只改说明。
- `apply` 会逐项报告 ✓ 或 ✗。✗ 的项改好后，只把这几项重新写进 初审.json 再跑 apply（上次的文件已经归档）。

**改写提示词的方法**：以当前提示词为底（记录.json 里每轮的 `prompt`，或清单原文），保留风格锁定句、背景句、发光句，只修改 Subject 部分，并针对问题加明确的约束。比如：
- 头太小 → "large head, about one third of the body height"
- 手臂粘连 → "arms clearly separated from the torso with visible gaps"

## 5. 试装与自查

`trial` 把每项的推荐图导入一个**临时游戏副本**（`美术资产/.trial_project`，正式游戏不受影响），然后：
- 截 4 张图（美术检查台三页加基因实验室），放进 `待复审/试装/`；
- 每项处理后的预览存为 `待复审/试装/<id>.png`；
- 生成审核页面。

交给用户之前，你先 Read 这几张截图：
- 上色后还能认出是哪个种族吗？
- 部件装到身体上，大小和位置是否大致合理？位置偏差不算重画的理由，通过后改 sidecar 就行（`art-pipeline.md` §6），这时用 note 告诉用户"位置可以调"。
- 背景放在战斗画面里会不会太抢眼？

发现真正的问题，就用 `{"redo": ...}` 撤回，或者用 `{"note": ...}` 补充说明，然后重跑 `trial`。

## 6. 用户复审：页面与服务器

- `serve` **必须用 run_in_background 运行**。它在 `http://127.0.0.1:8765/` 提供审核页面（端口被占用时自动换），并自动打开用户的默认浏览器。
- 接着告诉用户："浏览器里已经打开审核页面（没打开就双击 `美术资产/审核页面.html`）。每张图点「通过」或「不要」，不要的写一句原因，最后点「提交复审结果」。"然后附上这批有几项、每项一句话的推荐理由。
- 用户提交后，服务器把结果写进 `美术资产/复审结果.json` 并自行退出。你会收到后台任务结束的通知，这时立即跑 `user-apply`。
- 用户是双击打开页面的（file://）时，页面会下载 `复审结果.json`，并把结果复制到剪贴板：
  - `user-apply` 会自动去 `美术资产/`、工作区和浏览器的下载文件夹里找；
  - 用户也可能把 JSON 直接贴进聊天，你就把它存成 `美术资产/复审结果.json`，再跑 `user-apply`。
- 服务器默认 4 小时后自动退出（`--minutes` 可以改）。用户之后再复审时，重跑 `serve` 即可，页面上的选择会保留在浏览器里。
- 没有决定的项留在待复审，下次 `trial` 或 `page` 会再次出现。

## 7. 用户退回后改提示词

`user-apply` 会输出 `REJECTED <id> <用户意见>`。逐条把用户的话翻译成提示词修改：

| 用户说 | 改法（在提示词里加或改） |
|---|---|
| 太写实 / 像照片 | stylized, simplified shapes, flat cel shading, no photographic texture |
| 颜色不对 / 不是灰度 | strictly grayscale, no color at all except …（保留发光句） |
| 形状不像 | 用更具体的词重写 Subject，写清楚形状、部件构成和比例 |
| 太复杂 / 太乱 | fewer details, bold simple silhouette, readable at small size |
| 太简单 / 太素 | more surface detail on …, but keep the silhouette simple |
| 方向反了 | facing right, the attached end on the left side（按资产要求写） |
| 有多余的东西 | 把那个东西写进 "only …, nothing else"，并在 Subject 里删掉相关词 |
| 风格和其他图不统一 | 保持风格参考开启；用文字描述已通过图的线宽和明暗 |
| 主体太小 | the subject fills about 80% of the frame |

做法：写 `{"<id>": {"prompt": "完整新提示词"}}` → `apply` → `plan redo`（报费用）→ `gen redo` → 初审 → `trial` → `serve`。

告诉用户你改了什么，一句话就行，例如"按你说的头太小，我把头部比例写死成身高的三分之一"。同一项被退回 3 次以上时，先问用户是不是要调整整体风格方向，不要一直烧钱。

## 8. 同步进游戏

`sync` 会做三件事：
1. 把 `已通过/` 里新增或改动过的原图复制进 `游戏/art_inbox/`。同时写一份 `credits.json`：GPT 生成的图署名 "OpenAI <模型>（AI 生成；Claude 初审，作者复审通过）"，用户自己的图使用 `美术资产/credits.txt` 的最后一行。
2. 把用户放在工作区里的 zip、图片文件夹和零散图片一起导入。
3. 运行 `import_assets.sh`：抠图、上色、覆盖率统计、全量检查、截 4 张图。

导入过的包会被移进 `美术资产/_已导入的包/`，不会重复导入。

之后按 `art-pipeline.md` §4 的第 4–10 步继续：看截图，用 sidecar 对齐，然后在 `游戏/` 里 git commit。

## 9. 出错怎么办

| 输出 | 原因 | 怎么做 |
|---|---|---|
| 连不上 api.openai.com | 网络不通（中国大陆常见） | 让用户在 GPTapi.txt 加一行 `proxy=http://127.0.0.1:端口`（代理软件里能看到端口），或者 `base_url=中转地址` |
| Key 无效（401） | Key 复制错了或已被作废 | 让用户检查 GPTapi.txt（你不能打开它） |
| 需要组织验证（403） | gpt-image 系列要求先验证组织 | 用户到 platform.openai.com → Settings → Organization → Verify，生效后再试 |
| 模型不可用（404） | 账户没有这个模型，或中转服务里叫别的名字 | GPTapi.txt 加 `model=…` |
| 余额不足（insufficient_quota） | 没充值，或没绑卡 | 用户到 Billing 充值；工具会立刻停止 |
| 限流（429） | 请求太快 | 自动等待并重试，不用管 |
| 被安全系统拦截 | 提示词里有容易误判的词 | 改写提示词（避开 gore、blood、corpse、weapon 这类词），用 `{"prompt"}` 更新后重画 |
| 预计超过本次上限 | 预算保护 | 把费用告诉用户，同意后加 `--max-usd` |
| 接口不支持参数 xxx | 中转服务或旧模型不支持该参数 | 工具会自动去掉这个参数重试 |
| 某项生成失败 | 单项出错 | `status` 里会列出来；`gen redo` 会重试失败的项 |

检查 Key 和连通性不花钱：`art_studio.sh . ping`。

## 10. 费用参考（按 2025 年 gpt-image-1 官方价估算）

| 质量 | 1024×1024 | 1536×1024 / 1024×1536 |
|---|---|---|
| low | 约 $0.011/张 | 约 $0.016/张 |
| medium（默认） | 约 $0.042/张 | 约 $0.063/张 |
| high | 约 $0.167/张 | 约 $0.25/张 |

- 每张风格参考图会另加约 $0.015 的输入费用。
- 82 项、每项 3 张、medium 质量，第一轮大约 $11–13。算上重画和退回，全部做完通常在 $15–30。
- 只做定调批大约 $1；P1 大约 $5–6。
- `gpt-image-1-mini` 大约是这个价格的 1/5，但质量差一些。

## 11. GPTapi.txt 格式

```
sk-xxxxxxxxxxxxxxxx            第一行：Key（必填；写成 key=sk-… 也行）
base_url=https://中转地址/v1   可选：OpenAI 兼容的中转服务
proxy=http://127.0.0.1:7890    可选：HTTP 代理（也会读取环境变量 HTTPS_PROXY）
model=gpt-image-1              可选：模型名
quality=medium                 可选：low / medium / high
n=3                            可选：每项的候选数（1–8）
budget=3                       可选：单次 gen 的花费上限（美元）
style_ref=auto                 可选：auto / off（风格参考）
moderation=auto                可选：auto / low（low 可以减少误拦截）
max_rounds=3                   可选：每项自动重画的上限
```

编码可以是 UTF-8（带不带 BOM 都行）或记事本的"Unicode"。文件名写成 `GPTapi.txt.txt` 或 `GPTapi` 也能识别。没有这个文件时，会用环境变量 `OPENAI_API_KEY`。
